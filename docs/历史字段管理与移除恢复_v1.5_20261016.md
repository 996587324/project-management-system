# 历史字段管理与移除恢复 v1.5

日期：2026-10-16。本次为新增迭代说明，不覆盖历史需求文档。

## 入口及使用

- 主入口：共享模型与字段映射 → 历史字段管理。
- 工艺卡片：数据源字段选择旁的“管理历史字段”，公式变量的数据源选择也复用此入口。
- 设备卡片：卡片编辑中的“历史字段管理 → 搜索 / 移除历史字段”。
- 快捷入口打开同一个管理组件，不依赖新增菜单或动态路由。管理组件有明确的数据源模型时预选该模型；没有时要求手动选择，不默认操作另一个模型。

搜索支持字段原名、中文映射名、完整 JSON Pointer 路径；可以按可选/已移除/全部及最后出现时间筛选。服务端分页，前端每页支持 20、50、100 项，批量选择只针对当前页。没有手动配置中文名称的已发现模型，以及升级前仅存在快照的模型，也可以进入管理。

## 移除和恢复的业务含义

“移出字段库”不是删除设备数据：

- 不删除原始报文、设备字段最后值、卡片追溯、曲线历史和已产生的推送记录。
- 移除的是同模型字段路径的候选资格；A/B 共用此状态，不是仅当前卡片或当前用户可见。
- 人工移除后，新报文和旧快照回补不会自动恢复；设备当前快照包含该字段，也不会重新加入可选列表。
- 恢复后，字段可以重新选择，保留的共享中文映射和显示格式继续使用。
- 原有中文/格式映射属于元数据，不作为阻止清理的业务引用，移除时也不删除。编辑或导入这些映射不会恢复候选资格。
- 全部字段移除后，字段选择返回空列表，不重新补齐或报“没有历史字段”。历史重复路径的多个目录记录按同一逻辑字段统一处理。

## 引用保护

移除前扫描当前保存的业务配置，包括已停用、但尚未删除的配置：

| 引用类型        | 检查范围                                            |
| --------------- | --------------------------------------------------- |
| 设备卡片        | 展示字段、状态字段，以及附着这些字段的追溯/推送配置 |
| 工艺卡片和线体  | 数据源绑定、公式变量、独立曲线及附着字段的追溯/推送 |
| Three.js 机械手 | 展示字段、状态规则、报警原因来源路径                |
| Three.js 设备   | 展示字段、状态字段                                  |
| 模型报警        | 触发字段、报警原因来源路径                          |
| 线体产量        | 产量数据源字段                                      |

存在引用时整批不修改，返回字段路径、模块、配置名称及标识，需先到对应配置解绑。对象父路径绑定也纳入检查，避免仅比较完全相同字符串而遗漏引用。

中转管理的 WebSocket 参数追溯按订阅参数编码工作，不直接引用这套 HTTP JSON Pointer 目录，不会把不同协议的同名参数误判为同一字段。本次没有改变它的采集和保留规则。

绑定保存、公式配置保存、线体复制、字段管理写入共用 SQL Server 会话应用锁，防止引用检查后其他实例并发新增绑定；正常接收和业务只读查询不获取此管理锁。被移除字段不能绕过候选列表从绑定保存接口直接写入。

## 权限与审计

- 查询：平台管理员，或 `shared-dictionary.read`。
- 移除/恢复：平台管理员，或显式 `shared-dictionary.write`；服务端重复检查，不能只靠前端按钮控制。
- 所有状态修改要求 `confirm: true`，前端提供二次确认和 A/B 共用范围提示。
- 状态与成功操作审计在同一事务提交到现有 `SysUserOperationLog`。审计写入失败时状态回滚，不允许出现无记录的成功变更。
- 管理接口返回字段结构、时间与引用元数据，不返回其他设备的样例值或实际数值。

## 数据库升级

复用 `calmadmin` 中的 `EdgeDashboardModelFieldCatalog`，新增：

```text
IsSelectionDisabled bit NOT NULL DEFAULT(0)
```

`EdgeModelFieldCatalogSchema.Initialize` 在 CodeFirst 前为有数据的旧表添加有效 SQL DEFAULT，并回填为未移除；新表通过实体声明生成相同约束。新表、旧表及重复初始化均在隔离数据库验证，没有变更原主键、索引或历史字段数据。

接收侧的显式批量更新列不包含人工状态；快照补齐更新也明确排除此列。原 `IsDelete` 的自动恢复逻辑不再承担人工移除的语义。

## API

均为登录后的共享管理 API，不新增免认证或 MCP 删除工具。

| 方法与路径 | 功能 |
| --- | --- |
| `GET /api/shared-data/catalog/models` | 可管理模型列表 |
| `GET /api/shared-data/catalog/page` | `modelMark`、`keyword`、`removed`、`lastSeenStart`、`lastSeenEnd`、`current`、`size` 分页筛选 |
| `GET /api/shared-data/catalog/references?modelMark=...&id=...` | 引用位置 |
| `POST /api/shared-data/catalog/selection` | 批量移除/恢复 |

```json
{
  "modelMark": "CHUANPXX_JQR",
  "ids": [123, 124],
  "removed": true,
  "confirm": true
}
```

`removed:false` 为恢复。每次最多 200 个目录 ID，只能属于指定模型。返回 `applied:false` 时整批没有修改，`references` 为引用位置；界面最多展示该响应前 1000 处引用，并标识总数。

原有 `/api/shared-data/catalog`、各看板的字段选择接口继续保留，并统一过滤人工移除字段。
