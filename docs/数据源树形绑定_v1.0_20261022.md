# 数据源树形绑定 v1.0

## 使用方式

点击“模型 / 数据源设备”打开统一选择窗口：展开模型后选择设备，或直接输入模型中文名、模型编码、设备名称、设备编码搜索。搜索结果保留模型层级，设备下方显示实际编码及租户；中转设备还显示网关、连接。

- 模型只展开，不会把模型编码误保存为设备编码。
- 模型和设备分批加载，每次 50 条，可以继续加载；后端每页最多 100 条，不再把前 500 条误认为全部设备。
- 已保存设备通过完整复合标识精确回显，不依赖当前分页；当前设备会置顶到所属模型下。
- 未收到近期数据的快照设备仍可选；目录暂未找到旧设备时保留原绑定编码，不自动清空。
- 改选设备后更新字段选项；原设备相关的展示字段、状态或统计字段需重新配置，重选同一设备不清空。
- 字段仍复用既有历史目录、中文映射与实际值接口。工艺看板固定数值、公式变量等业务保留。

## 名称与模型归属

实时源按快照中的 `ModelMark` 分组，模型中文名来自现有共享映射。设备名称优先复用已配置的设备组件名称，其次机械手名称、设备卡片名称；仅使用当前授权线体内的名称作为别名。没有名称时显示实际设备编码。搜索可匹配上述已有配置名称，但不改写设备身份或建立新的名称配置表。

中转订阅已有设备名称可以直接展示和搜索。**现有订阅表没有模型外键，中转设备暂归“未分类模型”**，不会用 WebSocket 连接名称或其他租户的同名设备猜测模型。后续要人工指定中转设备模型，需要另行扩展订阅配置。

## 已适配入口

1. 小时产量看板：实时源和中转连接的数据绑定。
2. 生产看板：机械手数据、设备组件数据、线体产量绑定。
3. 设备卡片配置：实时设备绑定。
4. 工艺看板：关联设备、卡片参数及公式变量（共同复用 `SourceBindingEditor`）。
5. 中转数据追溯：来源业务设备及其订阅参数。
6. B 系统映射：订阅设备作用范围；全局默认、节点默认的语义不变。

业务数据集选择（例如日统计、报警记录）、连接本身的新增编辑、以及只读数据源列表不属于设备绑定，未替换为设备树。

## 统一接口

| 方法 | 地址                          | 作用                       |
| ---- | ----------------------------- | -------------------------- |
| GET  | `/api/source-catalog/models`  | 授权模型、设备数量及分页   |
| GET  | `/api/source-catalog/devices` | 模型内加载或跨模型搜索设备 |
| GET  | `/api/source-catalog/resolve` | 按旧绑定完整标识精确回显   |

公共参数：`purpose`、`kind`、`keyword`、`modelMark`、`page`、`size`；中转还可限定 `gatewayId`、`connectionKey`。

- `kind`：`Realtime` / `Edge`。
- `purpose`：`dashboard` / `device-card` / `process` / `hourly` / `trace` / `b-mapping` / `shared`，服务端根据业务校验权限，不相信前端传参作为授权。
- 实时标识：`sourceKey=TenantMark`、`deviceKey=DeviceCode`。
- 中转标识：`sourceKey=SourceId`、`deviceKey=网关DeviceCode`、`sourceDeviceCode=业务设备DeviceCode`。
- 旧 B 映射只有网关 ID 时，可使用 `gatewayId + sourceKey + sourceDeviceCode` 精确回显网关编码。

所有接口要求后台登录；模型列表、数量、搜索、回显均在分页前进行资源限制。SQL Server 资源标识按二进制排序规则匹配，避免默认不区分大小写造成跨资源命中。接口只返回选择所需元数据，不返回连接凭据、完整报文或业务字段实际值。

## 验证与发布

- 隔离数据库测试：520+ 快照、超过 500 条的分页和回显、中文模型/设备名、同名跨租户与大小写边界、中转设备及 B 系统资源授权。
- 真实 MVC：未登录 401、无业务权限 403、非法类型 400、camelCase 返回格式、全局访问过滤器和 Autofac 注册。
- 浏览器使用模拟数据验证：旧设备置顶、模型展开、中文搜索、选择后返回复合标识和实时/中转切换。
- 前端相关文件 ESLint/Prettier、接入回归测试及 A/B 独立构建。全量类型检查仍有项目既有错误，不能视为全项目通过。

**需要同时发布前后端。** 本次无数据库表结构变更、无 Redis、无新后台循环任务，不改变现有采集、统计、追溯、推送或 MCP 协议。不自动重新配置任何已保存数据；未重启用户现有服务、未提交或推送 Git。
