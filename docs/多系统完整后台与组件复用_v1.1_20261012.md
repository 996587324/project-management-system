# 多系统完整后台与组件复用 v1.1

日期：2026-10-12。本文件是新增迭代说明，不覆盖 v1.0。

## 1. 本次结果

A、B 是同一套业务源码构建出的两个独立后台站点，连接同一个后端。B 不再使用仅含工作台的简化界面，改为与 A 相同的侧边栏、页头、多标签页、主题设置、页面缓存、统一请求封装和动态组件加载器。两个系统各自维护名称、入口、首页及动态菜单。B 可复用 A 已登记的业务页面组件，并单独设置菜单名称、路由名、路径、父级、排序、启用状态和缓存选项。

## 2. 默认 admin 授权

后端启动执行一次性升级 `multi-system-full-backend-v2`：

- 对已有、启用、账号名为 `admin`（不区分大小写）且角色含 `R_ADMIN` 或 `R_SUPER` 的账号，授予 A/B 入口、全部业务权限、全部资源和全部 MCP 工具范围，并登记为平台管理员。
- 不创建用户，不修改密码，不给其他普通账号自动授予 B 权限。
- 升级完成后不会每次启动重新覆盖管理员已调整的授权或 B 菜单。
- 如果账号不叫 `admin`、已停用或不是管理员，不自动提权，应由平台管理员在“系统入口与统一授权”中配置。

完整权限表示后端授权不再将 B 一概拒绝；业务组件仍使用原本的接口和业务校验。权限并不替代必填业务配置，也不会修复组件内原有的独立缺陷。

## 3. 菜单和组件如何配置

### 首次升级

B 默认复制当前已有业务菜单元信息，并保留 B 自己的工作台。共享字典只保留一个入口，避免相同路径重复。A 继续使用原 `sys_menu`，B 新增 `SysApplicationMenuEntry` 存储独立菜单实例。

### 选择复用哪些业务

进入“系统入口与统一授权 → 系统入口与菜单 → B → 所属菜单”，多选需要复用的页面，保存。父目录自动补齐。已复制菜单再次保存不会覆盖 B 已修改的名称、路径和父级。取消选择会移除对应的 B 菜单实例，不删除业务数据或 A 菜单。如果仍有其他菜单挂在待删除目录下，会要求先处理子菜单。

### 单独编辑 B 菜单

以 admin 进入 B，在“系统管理 → 菜单管理”编辑：

- 组件路径可搜索选择已登记业务组件，例如项目管理、生产看板、边缘计算、日志等。
- 顶级菜单路由以 `/` 开头；子菜单填写相对路径，父级通过下拉选择。
- 顶级目录使用 `/index/index`；嵌套纯目录可留空。
- B 菜单编辑使用自己的主键和父级，不修改 A 的 `sys_menu`。
- 自定义路由名与组件原始业务权限分开，改名不会改变接口授权所需的权限。
- 菜单管理列表包含停用菜单，动态导航只加载启用且已授权的菜单。
- B 的菜单按钮权限元信息支持真实保存和移除；元信息不会自动生成业务按钮代码。

普通账号的 B 授权仍由平台管理员显式配置；不是“复制菜单就自动获得接口权限”。

## 4. 共享与独立的边界

| 内容                               | 当前行为                                               |
| ---------------------------------- | ------------------------------------------------------ |
| 系统名称、入口、首页               | A/B 分开配置                                           |
| B 菜单实例、名称、路径、父级、排序 | 独立于 A                                               |
| 登录令牌、标签页、主题和本地缓存   | 使用 `calmadmin:A:*` / `calmadmin:B:*` 分开            |
| 模型中文名、字段中文名和展示映射   | 平台共享一份                                           |
| 实时数据源和原始字段最后值         | 共用接收与持久化链路，按授权读取                       |
| 原有业务页面组件和接口             | 复用同一套实现                                         |
| 原有线体、卡片、看板布局等业务配置 | 当前仍是共享业务对象，不因切换前端自动复制或分库       |
| MCP                                | 一个 V2 服务，按当前用户所属系统的授权校验，并保留审计 |

**重要：修改 B 菜单不会修改 A 菜单；但是在 B 的复用业务页面修改共享线体、卡片或布局，会影响同一个业务对象在 A 的展示。本次没有实现业务配置的物理隔离。**

尚未实现按资源过滤的旧业务接口，仅允许“全部业务资源”加对应业务权限的账号使用。部分资源账号仍然拒绝这些旧接口，避免越权；可使用已经适配的共享数据或 MCP 授权接口。

- `Service/System/Applications/SystemApplicationMenuService.cs`：复制、编辑、树形查询和目录校验。

后端调整：

- `SystemApplicationSchema.cs`：一次性完整后台升级与默认 admin 双系统授权。
- `SystemApplicationService.cs`：组件选择目录、B 独立菜单配置。
- `MenuController.cs`：按系统分流、B 管理菜单查询。
- `UserInfoController.cs`：当前系统首页、B 管理员角色兼容。
- `SystemApplicationAccessFilter.cs`、`AgentWebSocketHandler.cs`：允许显式全资源授权的 B 使用已有业务和 Agent。
- 菜单 DTO 和 AutoMapper：启用状态、排序及原始业务权限标识。
- `tests/MultiSystemSmoke/Program.cs`：隔离数据库集成测试。

前端调整：

- `vite.config.ts`、`src/main.ts`：A/B 共用完整后台启动入口，构建时确定系统编码。
- `src/utils/system-applications/entry.ts`、`src/views/auth/application-entry.vue`：B 的统一控制台登录及一次性票据兑换。
- 路由守卫、菜单处理器、菜单 Store：B 动态菜单、系统首页及兜底 404 判断。
- 用户、标签页、设置、主题、iframe 缓存：按系统隔离；异常恢复只清理当前系统缓存。
- 菜单管理页、菜单编辑弹窗：B 组件选择、父级选择和独立菜单保存。
- 控制台：从 B 固定入口返回的登录握手，在登录成功后直接进入已选择的 B。
- 统一授权配置页：B 不再限于两个页面。
- 按钮权限指令和权限钩子：使用原始组件权限，不受自定义路由名影响。
- 移除不再使用的 B 简化布局、旧独立会话和重复操作追踪实现。
- `tests/full-admin-routing.mjs`：构建入口、缓存键、动态路由 Layout 复用测试。

## 6. 启动与发布

前端项目：

```powershell
pnpm dev
pnpm dev:b
```

A 默认开发端口 3006，B 默认 3007；两者代理目标按各自环境文件配置，均可连接同一个后端。

发布分别执行：

```powershell
pnpm build
pnpm build:b
```

A 输出 `dist`，B 输出 `dist-b`。发布为两个站点即可，不需要启动第二套后端。后台登记 A 的控制台地址 `http://主机:A端口/#/portal`，B 固定入口 `http://主机:B端口/#/auth/entry`。升级后需要重新启动后端、刷新两套前端并重新进入 B；旧简化 B 的登录缓存不迁成 A 的令牌。
