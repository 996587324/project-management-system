# 微信推送组件职责拆分 v1.2

日期：2026-10-17。本次为前端代码结构重构，不改后端、接口、数据库、动态路由和业务规则。保留 v1.1 文档。

## 拆分后的职责

文件均位于 `src/views/wechat-clawbot/`：

| 文件 | 职责 |
| --- | --- |
| `index.vue` | 五个 Tab、公共账号状态、顶部刷新与五秒刷新生命周期 |
| `components/ClawBotBindingTab.vue` | 绑定信息、MCP 推送开关、扫码入口和解绑 |
| `components/ClawBotBindingDialog.vue` | 二维码、扫码轮询、验证码、取消与绑定成功提示 |
| `components/ClawBotAiConnection.vue` | 原有 AI 连接配置与处理记录，保持独立组件不变 |
| `components/ClawBotMessageTest.vue` | 测试输入、发送条件、发送结果和结果清空 |
| `components/ClawBotReceivedRecords.vue` | 接收表格、类型显示和接收分页 |
| `components/ClawBotDeliveryRecords.vue` | 发送表格、结果显示和发送分页 |
| `composables/useClawBotRecordPage.ts` | 收发记录共用分页请求及旧响应覆盖保护 |

父页面缩减为约 190 行，不再放二维码流程、消息发送、表格列或各个业务分页状态。组件样式随业务组件移动，父页面只维护整体布局。

## 交互约定

- 账号通过只读 props 传入；绑定组件不直接修改父页面账号对象。
- 绑定/推送开关变更通过 `changed` 通知父页面刷新。
- 解绑通过 `unbound` 通知父页面清空旧测试结果并刷新。
- 扫码弹窗的 `confirmed` 表示绑定成功；点击开始测试通过 `start-test` 切换标签。
- 测试完成通过 `sent` 通知父页面刷新收发记录。
- AI 及收发记录暴露 `refresh`；父页面统一协调刷新，不额外增加子组件轮询计时器。
- AI 配置仍首次进入才加载；普通 Tab 不销毁组件，因此切换时保留输入、表单及各自页码。
- 离开页面后清除公共刷新计时器，扫码弹窗自行取消轮询及在途扫码请求。
- 接收/发送分页分别维护；翻页后晚返回的旧请求不能覆盖新页。
