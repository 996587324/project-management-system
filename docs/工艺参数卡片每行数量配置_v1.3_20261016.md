# 工艺参数卡片每行数量配置 v1.3

日期：2026-10-16。本次新增迭代文档，不覆盖原需求说明。

## 使用方式

进入“工艺看板配置 → 参数卡片 → 新增/编辑”，设置“每行参数数量”，保存配置后在产线工艺看板查看。

- 每张卡片独立设置，支持整数 1～6，默认 1。
- 线体已有的“每行数量”控制一行放几张卡片；本次配置控制一张卡片里每行最多显示几组 Key / Value，两者互不替代。
- 按字段原顺序从左到右、从上到下展示。状态圆点、数值精度、单位、双击查看历史功能保留。
- 配置数量是每行上限，不保证在很窄的卡片中强行显示相同数量；卡片变窄时自动减列，调宽时自动恢复，不修改保存值。
- 长参数名称、长数值和长单位支持换行，不通过裁掉数值来适配布局。

每组参数以 220px 为舒适最小宽度，组间距 16px。例如默认卡片边框/内边距下，两组约需实际卡片宽度 498px，三组约需 734px。

若设置多列后仍只显示一组，请调整实际卡片宽度：自由布局、横向布局可以调宽卡片；网格布局可减少线体的每行卡片数量。只修改配置中的卡片宽度不会改变现有网格均分宽度的规则。

## 数据保存及兼容性

继续使用原有 `POST /api/process-board/definitions` 保存，读取 definitions 和 runtime 接口时返回相同属性。

```json
{
  "kind": "Card",
  "columns": 3,
  "fieldColumns": 2
}
```

以上仅展示相关属性，完整保存仍需带上原有编码、名称、所属线体、版本和字段等配置。

- 新值写入现有 `ProcessBoardConfig.DefinitionJson`，沿用原有配置审计和版本机制。
- 不新增 SQL 列、数据表或索引，不需要数据库结构迁移。
- 旧 JSON 未包含此属性时，后端默认 1；前端对缺失或异常历史值也回退为 1。
- 此属性属于卡片级展示设置，不改变字段定义本身，因此不会因列数变化而更改字段身份及追溯比较输入。
- 保存后仍沿用原有版本和后台采样机制，新版本数值会在采样后更新；没有增加新的采样或推送任务。

发布时需要同时更新前后端。仅更新前端而使用不认识该属性的旧后端，无法保证新配置被保留。
