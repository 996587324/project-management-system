# 多系统名称加载修复 v1.2

日期：2026-10-12。新增迭代说明，不修改前面的 v1.0、v1.1 文档。

## 问题原因

B 构建时的 HTML 标题写死为“系统 B”，前端名称初始值也是该固定文字。
后端公开入口信息默认只查询 A，B 的实际配置名称要等票据兑换或用户信息加载后才更新。
名称更新时，已有浏览器标签标题没有即时同步，所以加载阶段或当前页面仍可能显示旧名称。

## 修改

名称来源保持为后台配置的 `SysApplication.DisplayName`，不把“工艺智能管理系统”写死在源码。

- `entry-information` 新增可选 `appCode=A/B`；缺省仍为 A，兼容原 A 登录入口。
- 请求 B 时返回 B 配置的名称，但统一控制台地址仍来自 A，保持原登录流程。
- 接口只公开系统名称、编码和控制台地址，不公开用户授权或业务数据；禁用 HTTP 缓存。
- 前端启动时异步读取当前系统名称，不阻塞路由、页面或业务初始化。
- 同一时刻启动与登录入口共享名称查询，请求最多等待 5 秒，不携带 JWT。
- 名称变化同步更新页头、侧边栏及浏览器标签；保留当前页面标题前缀。
- A/B 名称分别缓存为 `calmadmin:A:display-name` 和 `calmadmin:B:display-name`。刷新首屏立即使用已知名称，随后按后端配置刷新。
- B 首次访问尚无缓存时显示“正在加载…”，不再显示写死的“系统 B”。网络失败时保留已知名称。
- 已有登录响应或用户信息更新了名称时，较早发起的公开查询不会覆盖它。

## Diff 文件清单

前端：

- `vite.config.ts`：B 静态标题改为加载占位，不再写死名称。
- `index.html`：首屏读取当前系统名称缓存。
- `src/main.ts`：启动阶段异步加载配置名称。
- `src/utils/system-applications/client.ts`：名称缓存、标题同步、名称查询去重、超时和过期响应保护。
- `src/utils/system-applications/entry.ts`：统一控制台跳转复用名称查询。
- `src/views/auth/login/index.vue`：登录页使用同一个名称查询。
- `tests/full-admin-routing.mjs`：加载标题、A/B 名称隔离、名称刷新、请求去重与网络失败测试。

后端：

- `calmadmin/Controllers/SystemApplicationsController.cs`：按系统返回名称，控制台仍指向 A。
- `tests/MultiSystemSmoke/Program.cs`：匿名读取 B 配置名称、A 兼容及无效系统编码测试。

不新增数据库字段，不修改生产配置或真实系统名称，不提交或推送 Git。

## 应用方式

后端需重启或重新发布；B 前端需重启开发服务，或重新执行 `pnpm build:b` 并发布 `dist-b`。
随后刷新 B。后台已将 B 名称配置为“工艺智能管理系统”时，加载完成后的标签和界面会使用该名称。

测试使用隔离数据库及模拟浏览器环境，不改生产用户或业务数据。构建验证输出到 `.codex-temp`，不覆盖现有 `dist`。
