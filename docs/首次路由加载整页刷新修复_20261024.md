# 首次路由加载整页刷新修复

## 原因

开发环境中，动态路由加载此前未转换的页面时，自动导入插件会补入新的组件样式依赖。原配置的样式通配符未覆盖安装版本中的真实入口，Vite 在运行时发现新依赖并重新优化，可能重新生成公共依赖并触发整页刷新。

此前本地验证也多次出现 `new dependencies optimized`、`optimized dependencies changed. reloading` 日志。原 A/B 配置还共用 `node_modules/.vite`，不同应用的编译配置会相互覆盖缓存。

参考：[Vite 7 依赖预构建说明](https://v7.vite.dev/guide/dep-pre-bundling)、[依赖优化配置](https://v7.vite.dev/config/dep-optimization-options)。

## 修改

`project-management-system/vite.config.ts`：

- A/B 分别使用 `node_modules/.vite/system-a` 和 `node_modules/.vite/system-b`。
- 设置 `optimizeDeps.noDiscovery: true`，防止首次进入页面时触发依赖重新优化。
- 补齐当前页面使用的浏览器依赖和深层导入，包含富文本、Excel、图表、Three.js 等；CommonJS 依赖继续预构建。
- 根据已安装 Element Plus 的实际文件，枚举组件 `style/css` 和 `style/index` 入口，覆盖自动导入的样式。

不改动菜单导航、路由懒加载及正常热更新机制。开发服务首次使用新缓存时会先进行一次预构建；修改 Vite 配置、HTML 入口等本来就需要重新加载的操作仍正常生效。

## 验证

- `scripts/test-route-dependencies.ts` 扫描真实源码导入并与配置对照：37 个浏览器依赖入口全部覆盖；检查组件样式、禁用动态发现及 A/B 缓存隔离通过。
- 相关文件 ESLint、差异格式检查通过。
- A 模式用独立冷缓存启动，依次首次打开真实小时配置、工艺配置和富文本组件：页面启动次数始终为 1，测试输入的草稿保留。
- B 模式首次测试进程遭遇本机可用内存不足退出；降低测试进程内存上限重新启动后，首次加载相同页面均成功，启动次数为 1，草稿保留。此进程异常与路由触发整页刷新分别记录。
- 浏览器验证采用真实页面组件和 Vue Router，业务接口使用隔离内存数据，未修改真实业务配置。

复现入口：`scripts/preview-route-lazy.ts`、`tests/route-lazy-preview.html`。验证记录位于 `.codex-build/route-lazy/`。

## 后续新增依赖

新增浏览器第三方库或深层导入时，同步维护 `optimizeDeps.include`，运行 `pnpm exec tsx scripts/test-route-dependencies.ts` 后重启开发服务。Element Plus 的组件样式列表会自动跟随安装版本更新，无需逐个维护。
